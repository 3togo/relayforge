### "Hotspot service unavailable" — root cause and the fix shipped in the .deb

Live diagnosis on this machine: `/etc/wifi-hotspot.conf` was absent, so
`relayforge-service --native-networkmanager` exited 1 with
`Error: "Cannot open private configuration file"`, and systemd restarted it every
5 s (restart counter 84) because `RestartSec=5` is *slower* than systemd's default
`StartLimitIntervalSec=10` — so the rate limit never tripped. The settings window
could only report `ServiceUnknown: ... not provided by any .service files`.

Fix implemented (goes into the package):
- `config_store::MISSING` — a distinct error for "never configured".
- `main.rs` — on that error prints the path plus a runnable `--init-config`
  example, then `exit(17)` (`EXIT_MISSING_CONFIG`).
- Units (`relayforge-native.service`, `relayforge-create-ap.service`):
  `RestartPreventExitStatus=17`, `StartLimitIntervalSec=300`, `StartLimitBurst=10`.
  Note `RestartPreventExitStatus` only applies to the **main process**, which is why
  an `ExecStartPre=` variant was rejected — an ExecStartPre failure would not honour it.
  D-Bus activation can still re-trigger starts, so the widened `StartLimitIntervalSec`
  is what actually bounds the loop.
- `README.md` — new "Troubleshooting: Hotspot service unavailable" section.
- `tests/test_deb_packaging.py` — asserts the restart policy and that the rate-limit
  window is >= 60 s.
- Rebuilt `artifacts/deb/relayforge_0.1.0_amd64.deb` (build-deb.py refuses to
  overwrite, so delete the old file first).

Post-install steps are still manual by design: `dpkg -i`, `systemctl daemon-reload`,
`--init-config /etc/wifi-hotspot.conf --wifi-interface wlo2 --backend networkmanager`,
`systemctl start relayforge-native.service`. The package never generates credentials
or starts a service.

### Analysis: can the hotspot password be "set but not read"?
Facts established by reading the vendored UI:
- `settings/main.py:851` — `_collect_config()` **always** sends `PASSPHRASE`
  (`self.entry_pass.get_text()`) on every save, together with `**self.config_data`.
  So the entry must contain the real value; a blank entry would send `""`, which
  `validate_config` rejects, and omitting the key is only safe if the UI writes it that way.
- `settings/main.py:636` — the entry is populated from `conf["PASSPHRASE"]`, with
  `"12345678"` as the fallback. So if the service stopped returning it, the UI would
  silently save the factory default over the real password. **Omitting the secret from
  `GetConfig` without forking the UI is a security regression, not a fix.**
- `settings/main.py:866 _on_show_qr` — builds the `WIFI:T:WPA;S:…;P:…;;` payload client
  side and prints `Password: {pwd}` in the dialog. The "share with a guest" feature
  genuinely needs the plaintext.

Good news: the save path is **patch semantics** — Rust `config::merge` and Python
`merged = {**read, **conf}` both keep keys that are absent from the patch. So a UI that
omits `PASSPHRASE` unless the user edits it preserves the stored secret with no service
change.

OS-level exposure is already fine: `/etc/wifi-hotspot.conf` is `0600 root:root`, so the
file is unreadable by the desktop user. The only leak is the D-Bus API.

Design options recorded:
1. Split polkit actions — `manage` (allow_active=yes: Start/Stop/SetConfig/…) and
   `credentials` (auth_self_keep or auth_admin_keep: GetConfig). No UI fork; one prompt
   per session when opening settings. Small change: `relayforge-core` needs a second
   action id and `Service::authorize` needs an action parameter.
2. Write-only secret — `GetConfig` omits PASSPHRASE, adds `PASSPHRASE_SET`; QR becomes a
   service-side `GetJoinCode` behind the `credentials` action; requires forking
   `settings/main.py` (like `desktop/tray.py`). Strongest: the PSK never crosses the bus
   except through one explicitly authorized call.
3. Leave `allow_active=yes` (current) — any session process can read the PSK, rewrite
   settings and start/stop sharing.

### BUG: `psk-flags=2` made every native hotspot start fail
Symptom: GUI showed "Hotspot could not start / NetworkManager request failed".

Real cause (NetworkManager journal):
```
device (rf...): Activation: (wifi) access point 'RelayForge Hotspot' has security, but secrets are required.
device (rf...): no secrets: No agents were available for this request.
device (rf...): state change: need-auth -> failed (reason 'no-secrets')
```
`networkmanager.rs::profile()` set `802-11-wireless-security.psk-flags = 2`, which is
`NM_SETTING_SECRET_FLAG_NOT_SAVED` (**not** NOT_REQUIRED — NOT_REQUIRED is 0x4). With
that flag NM discards the supplied PSK and asks an agent; there is no agent, so the
activation dies. The pinned upstream probe sets **no** `psk-flags` at all; persistence
is already prevented by `persist=volatile`.

Isolated with a differential D-Bus probe (volatile profiles against the real NM):
- `psk-flags=2` → ActiveConnection disappears, activation fails
- **no `psk-flags` → State=2 (ACTIVATED)**
- `psk-flags=0` → also OK in principle; that run only failed with EBUSY from the
  previous child device still being torn down

Fix: removed the line (with a comment), and `tests/fake_networkmanager.py` now asserts
`'psk-flags' not in settings['802-11-wireless-security']` instead of `== 2`, so the
regression is caught by the fixture.

Also improved: a vanished ActiveConnection during activation now reports
"Native NetworkManager activation was rejected; see the journal" instead of the opaque
"NetworkManager request failed".

Verified live after reinstall + restart: Start returned
`active:true, state:active, iface:rf9dbe6890ca, phy_iface:wlo2, ssid:Hotspot, band:2.4`
while `wlo2` stayed connected to the upstream; `iw dev rf9dbe6890ca info` showed
`type AP, ssid Hotspot, channel 12 (2467 MHz)`; Stop cleaned up with no `rf` device and
no "RelayForge Hotspot" profile left.

**Lesson:** fixture-backed tests only prove the fixture. This bug was enshrined by an
assertion (`psk-flags == 2`) that matched the implementation instead of NetworkManager's
semantics. Anything that talks to real NM needs at least one run against the real bus.
