# RelayForge 0.1.1

Release candidate packages for Ubuntu 26.10 (amd64), using the native `create_ap` backend. These packages have not been published as a stable GitHub release.

## Changes

- Fix the NetworkManager discovery race that could reclaim a newly created virtual hotspot adapter.
- Handle tunnel and other non-Ethernet interfaces when saving and restoring forwarding state.
- Clean up confirmed stale hostapd control sockets without deleting live sockets or unrelated files.
- Preserve the original startup error when cleanup also fails.
- Keep the tray menu open during status refreshes.
- Display the installed package version in the About window.
- Show adapter type, interface name and available hardware details in Settings. Rename “Device” to “Wi-Fi adapter” and “Share from” to “Internet source.”
- Hide RelayForge's temporary `rfap…` adapters from both selectors.
- Check every listed Wi-Fi adapter's driver capability. Gray out adapters without Access Point support and explain why; they remain available as Internet sources.
- Offer optional patched NetworkManager applet and GNOME Settings packages with explicit version dependencies.

## Packages and installation

Choose **one** package variant:

- `standard/`: RelayForge with its own tray, settings editor and bundled GNOME Shell extension. Uses stock desktop network applications.
- `desktop-integrated/`: RelayForge plus patched `network-manager-applet`, its matching `network-manager-gnome` transition package, and `gnome-control-center`. Install all four packages together.

Verify the downloaded bundle from its root directory:

```sh
sha256sum -c SHA256SUMS
```

Then install the chosen variant:

```sh
sudo apt install ./standard/*.deb
# Or:
sudo apt install ./desktop-integrated/*.deb
```

The optional desktop packages target NetworkManager Applet `1.36.0-4ubuntu1` and GNOME Control Center `1:51.0-1ubuntu1`; their patched versions end in `+relayforge1`. They are not generic patches for other distributions or desktop versions. NetworkManager core is unchanged.

Installing RelayForge does not create hotspot credentials or enable sharing. Follow the repository's configuration instructions for a new installation. Existing configuration is retained on upgrade. Reopen Settings after upgrading; the tray detects updated code and reloads itself.

Removal deletes packaged programs. Purge also removes the packaged login-autostart configuration. The administrator-created `/etc/wifi-hotspot.conf` is deliberately retained, including on purge.

## Validation and scope

The `Release validation` GitHub Actions workflow builds the release artifacts and checks:

- The complete Rust and Python test suites, pinned vendor contents, and normal/sanitized applet menu tests.
- Clean installation, upgrade from the actual previously pushed 0.1.0 revision, removal and purge in isolated Ubuntu 26.10 containers for both variants.
- Configuration preservation and the installed service's Start/Stop protocol using a private bus and demo backend.

Container tests do not exercise physical Wi-Fi or a full desktop session. Earlier physical validation covered two Android devices, DHCP, DNS, internet access and hotspot stop/start. Live desktop integration checks ran under XFCE. Full GNOME Shell and KDE Plasma sessions remain unverified; KDE uses the separate RelayForge tray, with no native Plasma Networks panel patch.

Before publishing these as a stable release, review the workflow results and these remaining desktop-validation limits. `SOURCE_REVISION` identifies the exact source used for each generated package bundle; `SHA256SUMS` covers all packages, these notes and that revision record.
